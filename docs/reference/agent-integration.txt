## 0. 结论先行

1. **人设不会必然分裂**——只要满足"三个唯一"：**唯一的记忆存储、唯一的提示词拼装、唯一的写入闸门**。执行体是"对话 API"还是"agent"不影响人格连续性；裂开的是"两个记忆源 + 两套 prompt 拼装"。
2. **值得接，但接法是"她是被 agent 驱动的人格"，不是"agent 顺便扮演她"**：
   Miracii 继续做**人格与记忆的家**（`persona/<id>/` + 星图 + 积温），agent 做**她的手和眼睛**（浏览、观看、账号、资料）。
3. **账号可以用，但要"能力阶梯"而不是"开/关"**：只读 → 受控读取 → 提议动作 → 人确认执行。发布类动作默认关闭。

## 1. 对话 API 与 agent 框架，真实差别在哪

不是"多了几个函数"，而是**七件事变了**。逐项对照 Miracii 现状（✅ 已有 / ⚠️ 部分 / ❌ 没有）：

| # | 机制 | 对话 API 的做法 | agent 框架的做法 | Miracii 现状 |
|---|---|---|---|---|
| 1 | **循环** | 一次请求 → 一次回复，结束 | `while`：模型要工具 → 执行 → 结果回灌 → 再问，直到不再要工具 | ❌ `/api/chat` 是单轮流式 |
| 2 | **工具** | 无 | 工具用 JSON Schema 声明（名字/参数/描述），模型 function call，结果以 tool 消息回灌 | ❌ 没有工具面 |
| 3 | **状态** | 消息历史 + 一份 system prompt | 历史 + **工具中间态** + 工作区文件 + 持久记忆 | ⚠️ 有历史与记忆，缺工具中间态 |
| 4 | **提示词拼装** | 一次性拼好 | 每轮重拼：人格 + 记忆召回 + 环境 + 工具手册 + 预算裁剪 | ✅ **已有一个拼装点** `persona.system_prompt()`（人格/常驻设定/工作台/词条/记忆召回/时间块），这是最大的资产 |
| 5 | **失败与上限** | 报错即结束 | 步数上限、超时、工具报错回灌给模型自纠、可中断 | ❌ |
| 6 | **权限与审批** | 无需 | 每个工具一条策略；危险动作走审批；沙箱 | ❌（但界面命令窗口的**白名单分发器**思路可以直接复用） |
| 7 | **调度** | 用户发起 | 定时/事件触发的**自主 turn** | ✅ `heartbeat` 已经是调度器（积温、巩固、提醒都在上面） |

**所以"从对话 API 升到 agent"要补的就是 1、2、5、6 四块；3、4、7 我们已有或接近。**

### 1.1 一次 agent turn 的最小骨架（与具体框架无关）

```python
messages = [{"role": "system", "content": system_prompt(persona, recall_text)}, ...history]
for step in range(MAX_STEPS):                       # 1 循环 + 5 上限
    reply = llm.chat(messages, tools=TOOL_SCHEMAS)  # 2 工具声明
    if not reply.tool_calls:
        return reply.text                           # 收敛
    for call in reply.tool_calls:
        result = dispatch(call, policy=POLICY)      # 6 权限闸门
        messages.append({"role": "tool", "content": result})   # 3 状态回灌
return "（这轮没想完，先说这么多）"                  # 兜底文案
```

这 20 行就是"对话 API → agent"的全部本质。剩下的都是**工程**：工具的幂等、超时、审批、观测、成本。

## 1.2 从 DSH 实现拆出来的四条硬约束

来源：[dsh-agent-architecture.txt](dsh-agent-architecture.txt)（子代理读编译后 bundle，97 处已核实，
行号绑 `dsh-agent-loop` 0.2.1-rc.5；asar 内无 `src/*.ts`，升级后行号会漂）。

| 约束 | DSH 的做法 | 对 Miracii 的意义 |
|---|---|---|
| **事件日志是唯一真源** | 只追加 `turn/start → step/start → tool/call → tool/result → turn/end`；`messages` 由 `deriveMessages()` **派生**；**请求里没有 `system` 字段** | 我们已有 append-only 的星图与积温台账；agent 轮次也该落成事件流，而不是只存最终对话。顺带解释了生态里"Creator mode 重启即失"——内存态的插件没落事件 |
| **工具结果按模型给出的顺序提交** | 并行有界池（默认 10）+ 独占屏障，但结果**必须按模型顺序回灌** | 将来做工具面时，`messages` 追加要按调用顺序，不能按完成顺序——否则模型会错配结果 |
| **工具失败是数据，不是中断** | 失败变成模型可见的 error result，**轮次继续** | 我们惯用的 `try/except: pass` 在 agent 里是要淘汰的：错误必须回灌给模型自纠 |
| **故意没有步数上限** | DSH 不设内置上限 | 我们必须自设 `MAX_STEPS` + 超时 + 费用闸——单人项目最怕一夜烧光 token |

两条可以直接抄的设计判断：

1. **提示词每步重拼**（段 order + 变量 + 工具 schema 在同一次 `assemble` 里）。这与我们的
   `persona.system_prompt()` 是同一位置的两种实现——我们已经站在正确的位置上。
2. **预算**：DSH 把 `AGENTS.md` 当 **user 消息**注入、预算 65536 字节。**预算可以抄，注入方式不建议抄**：
   人格设定进 user 消息会污染对话语义（模型会当成"对方说的"），我们要留在 system 段。

## 2. 三种拓扑（Miracii 该站哪一个）

| 拓扑 | 形态 | 优点 | 缺点 |
|---|---|---|---|
| **A. Miracii 自己长出 agent 循环** | 在 `app/` 里加 loop + 工具；记忆与 prompt 天然单一 | 无跨运行时；调试简单；红线好守 | 要自己重造工具生态（浏览、账号、观看都不便宜） |
| **B. Miracii 当"人格与记忆后端"**，DSH agent 当执行体 | agent 每轮调 `POST /api/agent/context` 拿 system prompt + 记忆；写完调 `/api/agent/commit` 落库 | **直接吃到生态**（bili-scroll/whale、websearch、IM、情绪引擎）；人格与记忆仍单一 | 两套运行时（Python + Node）；每轮多一跳；写入必须走闸门 |
| **C. 混合**：Miracii 占 A，生态插件通过 bridge 供工具 | 自己控循环，只借用"世界读取"能力 | 兼顾 | 桥要写；两套仍在 |

**推荐：先走 B 的只读半边（`/api/agent/context` + 工具白名单），再决定要不要把循环搬回来（C）。**
理由：生态里最贵的是"看世界 + 账号"，那正是 Miracii 不想重造的；而"人格与记忆"我们已经比他们强。

## 2.5 通道分离：对话不是 agent 的一个工具循环

> 人提出的问题：引入 agent 之后，**和我直接对话的那个端口应该是什么？** 她自主刷视频时我跟她说话，
> 不该把"读视频的思考 token"和对话上下文混在一起；也许 agent 只当大脑，另有一个小代理负责"写出那句话"。

**结论：把系统切成三条通道，对话永远走快路，agent 只走慢路，慢路的产物必须"蒸馏"后才能进对话。**

| 通道 | 触发 | 形态 | 延迟 | 只写这些 |
|---|---|---|---|---|
| **对话（快路）** | 用户说话 | **单轮、流式、无工具循环** | 首 token < 2s | 对话消息 |
| **认知/行动（慢路）** | 定时 / 事件 | agent 循环 + 工具面，可跑几分钟 | 分钟级 | **事件日志 + 记忆候选** |
| **简报（桥）** | 对话前 | 把慢路的成果压成 ≤300 字的「她此刻的心事/刚看到什么」 | 读文件，0 成本 | 不写 |

四条硬规则：

1. **对话通道永不做工具循环**。回复一句话要 3 轮工具 + 4 次模型调用，是"大炮打蚊子"，
   而且每轮都会把工具输出灌进上下文——这正是人担心的连贯性问题。
2. **慢路产物只能以"简报"进对话**，绝不把工具轨迹、原始网页、视频抽帧塞进对话上下文。
3. **两条路共用同一个记忆存储与同一个提示词装配器**（只是预算不同）——"三个唯一"的延伸。
4. **两条日志**：`chat`（对话，用于连续性与复盘）与 `events`（认知，用于重建"她想什么"）。
   DSH 把两者放在同一条事件流里（messages 由日志派生、请求里没有 system 字段），
   那是**框架视角**；**产品视角**必须分开，否则工具输出会污染对话。

### 大脑 / 嘴 / 小代理

- **大脑** = 慢路的状态（事件日志 + 记忆 + 积温）。它不直接说话。
- **嘴** = 对话通道的**一次** LLM 调用，输入是「人格 + 记忆召回 + 简报」，输出一句话。
  **同一个模型、同一套人格**，只是不循环——这样声音不会变。
- **小代理** = 需要多步推理时，后台起一个 subagent 想完，交回一份简报（DSH 的 subagent 模式）。
  它读原料，对话通道只读它的结论。

### 顺带回答"supervisor 该不该有更多能力"

该有，但**由 Miracii 主导**，不是装别人的插件：

- `persona/<id>/room/`：**她的小屋**（书架 `shelf/`、便签 `notes/`、手账 `diary/`），
  supervisor 负责往里放东西，对话里她可以引用"我书架上那本"。
- `capabilities.json`：能力注册表（名字 / 级别 L1–L4 / 是否需人确认 / 实现位置），
  **Miracii 自己解析与执行**，外部插件只是"能力提供者"，不是"宿主"。
- 依据：生态里 `dsh-fish` 就是"工具面即人格边界"——她只能看见给她的工具。这告诉我们
  **给哪些能力**本身就是人格设计的一部分，所以注册表必须由我们掌权。

## 3. 接口草案（B 拓扑）

```
GET  /api/agent/context?persona=miracii&scan=<本轮对方的话摘要>
     → { system_prompt, recall: [{block, fp, why}], warmth: {...}, tools_allowed: [...] }
POST /api/agent/commit
     → body: { persona, kind: "turn"|"event"|"observation", texts, evidence, tool: "bili_watch" }
     → 服务端：schema 校验 → 注入守卫 → append-only 写入 → 返回 id（可回滚）
POST /api/agent/turn  （可选，替代 commit 的直接通道：把一问一答落成一条对话）
```

三条设计约束：

- **只暴露"拼好的 prompt"和"结构化的记忆块"，不暴露文件路径**——否则 agent 会绕过拼装点自己拼，那就是分裂的开始。
- **写入只有一个入口**（`commit`），且**只能追加**；人格文件与星图**不许 agent 直接改**（这正好对上生态里 `growth_commit` 的做法）。
- **鉴权**：只绑 `127.0.0.1` + 一次性 token（写进 `~/.dsh/` 或环境变量），不放到 `--lan`。

## 4. 权限与账号：能力阶梯（回应"可以限制"）

| 级别 | 能力 | 落点 | 默认 | 限制手段 |
|---|---|---|---|---|
| L0 | 只读本地（记忆/星图/温度） | 现有 | ✅ 开 | 无 |
| L1 | **只读世界**：搜索、B 站字幕/评论/弹幕、RSS | agent 侧插件 | ✅ 开 | 域名 allowlist；超时；结果截断 |
| L2 | **账号读取**：cookie/扫码登录，只读自己的通知/私信 | agent 侧 | ⚠️ 需人开 | cookie 单独文件 0600；独立 profile；只读工具白名单；频率上限 |
| L3 | **对外发布**：评论、私信、发帖、刷弹幕 | agent 侧 | ❌ 默认关 | **人确认**（一次一批）或日配额；内容落日志；可回滚 |
| L4 | 自写插件/改运行环境 | 无 | ❌ 永不开（本项目） | 见红线；只抄 evolver 的安全模型 |

落地手段（都在我们这边可控）：

- **工具白名单在服务端判定**，不由 agent 自报；`commit` 校验 `tool` 字段是否在白名单。
- **动作分级表**（`docs/AGENT-POLICY.txt`，待建）：每个工具一行，标 L 级别与是否需要人确认。
- **一次一批 + 可回滚**：L3 动作写 append-only 日志（`data/agent-actions.jsonl`），带 `undo` 提示。
- **频率与静默**：复用积温的冷却与安静时段——她连"想说话"都被限流，发评论当然更该限。

## 5. 人设不分裂的三个前提（以及反例）

| 前提 | 保证方式 | 反例会怎样 |
|---|---|---|
| **唯一记忆存储** | agent 不落自己的记忆；每轮从 `/api/agent/context` 取，写完走 `/api/agent/commit` | agent 自带 `fish-memory` 一套 JSON → 两套记忆互相漂移 |
| **唯一提示词拼装** | 只暴露拼好的 system prompt；不暴露原始文件 | agent 自己拼 prompt → 人格随 agent 版本漂移 |
| **唯一写入闸门** | append-only + schema + 注入守卫 | agent 直接改 `persona/` → 人设被"悄悄改写" |

网友的人设确实没裂，是因为他们的**插件本身就是唯一记忆源**（`fish-memory`/`hierarchical`）——即
"插件即人格容器"。我们与他们只差一件事：**谁当那个唯一容器**。答案是 Miracii。

## 6. 记忆插件原理 → 我们能承载多少

（详细拆解见 [memory-plugin-principles.txt](memory-plugin-principles.txt)，这里只给结论）

| 他们的机制 | 我们的文件树 + 星图能否承载 | 说明 |
|---|---|---|
| 加权遗忘（半衰减，不删只淡化） | ✅ 已接近 | 星图四档 λ 就是它；缺"按记忆条目单独设半衰期" |
| 事实键取代（同键新条覆盖旧条） | ⚠️ 可加 | 语义层已有 `keys`，可加 `superseded_by` 派生字段（不改原文） |
| 分层注入预算 | ⚠️ 可加 | 现在按块数/字数硬截，可改成按层分配 |
| 事件溯源（append-only + 派生快照） | ✅ 结构相合 | 星图账本、积温台账已是 append-only；可再加"事件流" |
| 召回解释（为什么想起这条） | ⚠️ 缺 | 只读投影能便宜地补上 |
| 记忆体检（矛盾句/快忘的/快固化的） | ⚠️ 缺 | 纯只读，性价比最高 |
| 按人隔离 + 私密标记 | ❌ 暂不需要 | 单人使用；多人再谈 |
| 虚拟时钟/作息/Dream | ⚠️ 部分 | heartbeat 有节拍，缺"她的一天" |

## 6.1 从记忆插件原理拆解里抄什么

来源：[memory-plugin-principles.txt](memory-plugin-principles.txt)（616 行，8 个插件按七问拆 + 10 条失败模式；
证据取自 npm 发布包源码，带版本与行号）。

### 三条值得抄

| 机制 | 他们的做法 | 我们怎么落 |
|---|---|---|
| **门槛只卡证据，衰减只进排序** | `fish-memory` 返工后的结论：证据分 `C = s/(s+0.8)`、阈值 `0.3`；**衰减与新鲜度只参与排序**，所以"调衰减不会误伤该想起的" | ⚠️ **我们正好相反**：`recall` 的排序是 `relevance × decay × novelty` 再取前 8 —— **衰减是乘数，会直接决定能不能进提示词**。建议改成：**证据门槛决定"能不能进"，decay/novelty 只决定"排第几"** |
| **事实键 + 已被取代** | 同键只留最新；旧条目标"已被取代"，保留但**不再召回**；并写明「**绝不从正文猜键**」 | 语义层已有 `keys`；在 sidecar 加 `superseded_by` 派生字段即可，**不碰正文** |
| **召回 trace 逐条记 omission** | 每条没进提示词的都记原因：`below_threshold` / `limit` / `budget` / `duplicate`；另有"快忘了 / 快固定"体检 | 我们有 `engine_explain`（积温），记忆侧缺同款；`--review` 加一节即可 |

### 三个坑（他们已经踩过）

1. **TTL 删除**：重要但不常提的记忆**最先死**。→ 我们不做 TTL；星图只淡化不删。
2. **每轮 LLM 固化**：成本、延迟、失败面都翻倍。→ 我们的巩固走 `heartbeat` 节拍，**不是每轮**。
3. **覆盖式摘要**：没有归档就不可回溯。→ 我们全是追加写。

### 一句话判断

**文件树 + sidecar 完全能承载上面三条**（都是投影层改动，不碰 `persona/` 正文）；
承载不了的是"每轮固化""向量检索""事件溯源重放"——**这三样我们本来也不打算做**。

| 阶段 | 内容 | 风险 | 需要什么 |
|---|---|---|---|
| **P0** | `/api/agent/context` + `/api/agent/commit`（只读 + 追加）+ 工具白名单校验 + token | T1 | 人开一个 agent 试跑 |
| **P1** | L2 账号读取（先 B 站字幕/评论只读）+ 动作日志 | T2 | 你提供账号与边界 |
