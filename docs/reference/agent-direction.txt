## 0. 一句话结论

那波生态真正的增量不是"权限更多"，而是**她第一次有了自己的信息来源**——这恰好是 Miracii
现在最缺的一环（沉浸度没有真实来源、主动开口只有"想你"一个理由）。
建议走 **只读环境 → 受控阅读** 两步；**不要**接入账号类与自写插件类能力。

## 1. 事实基线（来自调研，不重复论证）

- 「全民养鱼」**不是官方项目**，没有统一提出者；是 2026-10 中下旬 B 站二创 + DSH 插件 + 批量小号叠加的结果。
- 接口**不是 MCP**：原生形态是 **DSH/Cordis 插件**（`inject` 服务 + `ctx.tools` 的 JSON Schema 工具 +
  `cordis.patch.yml` + `dsh plugin add`）；MCP 只是可选桥。
- **agent 自写插件仍是实验态**：官方 Creator mode 只在内存里试验、重启即消失；社区用 Creator Mode+ / evolver 补落盘。
- 与"人设运行"最相关的三组插件：
  - **看世界**：`bili-scroll` / `bili-whale`（刷 B 站、读字幕、发评论私信）、`dsh-websearch`（聚合搜索）
  - **有生活**：`fish-soul`（虚拟时钟/作息/Dream/主动开口）、`speak-up`（按概率主动搭话）、`fish-mood`（36 情绪 + 半衰期 + 关系暖度）
  - **记忆可塑性**：`fish-memory`（遗忘曲线/事实键/召回解释）、`hierarchical-fishmemory`（浅层 7 天 TTL、人格手记）、`soul-md`（人设卡 + 文件记忆）

## 2. Miracii 现在缺什么（对照）

| 能力 | 生态里的做法 | Miracii 现状 | 缺口的后果 |
|---|---|---|---|
| 世界输入 | 刷 B 站、搜网页、看视频抽帧 | **零输入**：她只知道你说过的话 | 沉浸度没有真实来源（本轮刚把假的关掉）；主动开口只有"想你" |
| 生活节律 | 虚拟时钟、作息、Dream、随机主动 | 有巩固节拍与积温，但**没有"她的一天"** | "人格生活化"无从谈起 |
| 情绪引擎 | `fish-mood`：36 情绪、半衰期、关系暖度、**只改表达不改事实** | 积温六轴 + 对话注入 | 方向一致；他们的"只改表达不改事实"值得抄进红线 |
| 记忆可塑性 | 遗忘曲线、事实键去重、召回解释、浅层 TTL | 星图 sidecar（衰减弱、召回计数）+ 分层文件树 | 我们的**可审计性更强**；他们的**遗忘与解释**更细 |
| 多平台 | QQ/B 站/抖音/多 IM | 只有本地网页 + 桌面提醒 | 不是当前瓶颈 |

## 3. 三条接入路线（代价 vs 收益）

### A. 只读环境（推荐先做）

**做法**：新增 `environment` 模块，每轮给 system prompt 附一段**只读**的"她此刻所处的环境"：
本地时间、星期、手头的事（来自显式活动源）、以及**人放进去的世界摘要**（见 C 的文件契约）。

| 项 | 评估 |
|---|---|
| 收益 | 立刻补上"沉浸度/主动开口的真实动机"；prompt 里多了可引用的现实锚点 |
| 代价 | 小：一个模块 + 一段 prompt + 一条测试；无权限面无账号 |
| 风险 | 低（只读、本地） |
| 与红线 | 完全不碰：不改记忆、不做终端、不信输入 |

### B. 受控阅读（第二阶段）

**做法**：`data/library/` 放人给的链接/PDF/markdown；她"想看书"时由 supervisor **翻开一篇**并读完，
产出摘要进记忆（作为"一段经历"），之后可以主动提起。这就是你说的"她想看书了，supervisor 给她翻开书上的内容"。

| 项 | 评估 |
|---|---|
| 收益 | 主动开口第一次有"我读到了什么"这种真实理由；沉浸度有了**真活动源** |
| 代价 | 中：库目录 + 阅读流水线 + 与 supervisor 的接入 + 记忆写入的复核 |
| 风险 | 中：**写入记忆**必须走既有复核（examiner），且只写"经历"，不改人格/设定 |
| 不碰 | 不做 B 站/QQ 账号（那是生态里的主战场，也是争议来源） |

### C. 完全自驱 / 自写插件（**现阶段不做**）

生态里这块（Creator Mode / evolver）本身还是实验态：Creator mode 重启即失，evolver 才补上
"提案→校验→挂载→打分→回滚"，且**只允许 `kind:"tool"`、禁 net/shell/fs/eval、32 KiB、前三次固化要人确认**。

对 Miracii 来说，这直接撞两条红线（界面不做真终端、不改记忆与设定），且复核成本会成倍上涨。
**结论：不做功能，但抄它的安全模型**——将来若要扩展能力，就按
「提案 → 校验 → 挂载 → 打分 → 固化/回滚，且只允许无副作用的工具」来设计。

## 4. 接口设计（怎么接，而不是"装哪个插件"）

Miracii 是 Python/FastAPI，**装不了 Cordis 插件**。真实可行的接法是**文件/HTTP 契约**：

| 契约 | 形态 | 谁写 | 谁读 | 优点 |
|---|---|---|---|---|
| **世界摘要** | `data/world/<日期>.md`（人可读的 Markdown，≤2 KB） | 外部 agent / 你 / 将来的 watcher | `environment` 模块 | 零耦合；可审计；坏了删掉即可 |
| **阅读队列** | `data/library/<id>.md` + `library/index.json` | 你或外部 agent | supervisor 的阅读流水线 | 同样是文件契约，便于复核 |
| **只读查询** | `GET /api/world`（今日摘要 + 环境块） | — | 面板 / 命令框 | 观察用，不改状态 |
| 不推荐 | 让外部 agent 直接调 `/api/chat` 扮演她 | — | — | 会出现**两个记忆所有者**，人设与记忆立刻分裂 |

**关键原则**：Miracii 永远是**记忆与人设的唯一所有者**；外部智能体只提供**输入**（世界/资料），不代她说话。

## 5. 对现有模块的影响面

| 模块 | 变化 |
|---|---|
| `app/warmth.py` | `immersion` 的真实来源变成"活动源"（A/B 落地后）；`immersion_from_backlog` 保持关闭 |
| `app/heartbeat.py` | 阅读流水线挂在巩固 tick 之外；主动开口的"由头"从"想你"扩到"读到/想到" |
| `docs/WARMTH.txt` | §2.2 的 immersion 来源说明要改 |
| `docs/BACKLOG.txt` | 新增 A/B 两项，删掉"环境块与 persona_state 没做"的旧条目 |
| 新增 `app/environment.py` | 只读环境块（A） |

## 6. 分阶段

| 阶段 | 内容 | 人可感 | 风险 |
|---|---|---|---|
| **P0** | `environment` 只读块 + `data/world/` 文件契约 + `GET /api/world` | 是（她的回话里开始有"今天/这几天"的现实锚点） | 低 |
| **P1** | `data/library/` + 阅读流水线（读完写一篇"经历"进 memory，走复核） | 是（她会主动说"我读到……"） | 中（写记忆） |
| **P2** | `persona_state`：她自己的"暂离/在忙"（由活动源驱动，与 `user_state` 对称） | 是（她偶尔"没空理你"） | 中 |
| **不做** | 账号接入（B 站/QQ/多 IM）、自写插件、批量小号、刷评论 | — | 高 |

## 7. 风险与争议（必须写下来）

- **账号与 ToS**：生态主力是"刷 B 站/发评论/私信"，涉及账号凭据与平台条款；社区已出现
  「大肥鱼清除计划」这类反制插件——说明这种做法在普通用户那里引发反感。**Miracii 不碰。**
- **批量小号**：引爆点正是"XX 在运营"式批量账号。我们不参与，也不为它设计。
- **记忆所有权**：任何"让别的 agent 扮演她"的方案都会导致记忆分裂；本方案明确禁止。
- **可塑性记忆的诱惑**：他们的"记忆会自己长结构"很吸引人，但 Miracii 的星图+分层文件树
  **可审计性更强**，且已经有复核流程。建议**先抄他们的"召回解释"与"遗忘曲线"这两个点**，不换架构。

## 8. 待你拍板的三件事

1. **P0 的"世界摘要"谁来写**？(a) 你手动丢文件；(b) 我写一个只读 watcher 定期抓（需要指定源）；(c) 让外部 DSH agent 生成。
2. **P1 的阅读是否允许写记忆**？如果允许，写进哪一层（`episodic` 作为经历，还是 `impression` 作为印象）？
3. **P2 的 `persona_state`** 要不要与积温耦合（例如"她在忙"→ `immersion` 高→ 连接需求涨得慢）？

## 9. 可借鉴清单（调研给出的八条，按"能不能马上用"排）

| # | 借鉴点 | 出自 | Miracii 怎么用 | 代价 |
|---|---|---|---|---|
| 1 | **只读记忆体检** | 生态共识 | 我们已有 `--stats` / `--view` / `--review`；再补一份"记忆健康"（星点衰减分布、重复块、未入册块） | 小 |
| 2 | **加权遗忘（不删只淡化）** | `fish-memory` | 星图已经是这个方向；可把"半衰期 + 重量"写进召回解释 | 小 |
| 3 | **召回解释** | `fish-memory` | `--view` 里已有 `engine_explain`；记忆侧缺同款（"为什么注入了这块"） | 小 |
| 4 | **事实键去重** | `fish-memory` | 语义层已有 `keys`；可补"同一事实多条 → 只留一条" | 中 |
| 5 | **分层注入预算** | `hierarchical-fishmemory` | 现在靠 `MAX_HITS=8` 与 `BLOCK_CHARS`；可改为按层给预算 | 中 |
| 6 | **事件溯源（append-only + 派生状态）** | `dsh-fish` | 星图账本与积温台账已经是 append-only；**总结与性格**可再走一次 | 中 |
| 7 | **立场清单上限 / 身份字数预算** | `dsh-fish` / `soul-md` | 防人格膨胀：给 "always_lore / 设定" 加字数与条数上限 | 小 |
| 8 | **四阶段成长门** | `dsh-fish` | 与我们"分段进化"的想法一致，可作为人格成长的门槛设计参考 | 大（暂不做） |

**明确不借鉴**：批量小号、刷评论/私信、账号 cookie 接入、`danger-full-access` 权限模型、
"安装即授权"的插件供应链（**插件就是宿主进程代码，工具审批不沙箱化**——这条风险调研里写得很清楚）。
