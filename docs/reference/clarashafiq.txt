## MemoryConstellations：可审计记忆管线

数据流：原始消息 → Scribe 原子观察（带精确引文）→ 待裁决证据池 → Claim 审查 → 星座 / Episode / Saga → **Facts / Status / Judgment 三条独立发布流** → 检索投影 → 聊天注入包。

**原则（比实现更值得抄）**：模型只提议，**只有宿主程序在校验证据、版本、租约与 CAS 条件后才写正式表**；Judgment（第一人称看法）有独立证据门，失败不得覆盖旧值。

## sts2-companion-bridge：读外部游戏状态

四模块：`server/sts2-state.js`（Express + Bearer + 内存缓存 90s，**不落库**）、`server/game-context.js`（游戏 JSON → 自然语言，17 种画面）、`bridge/sts2_bridge.py`（Windows 侧轮询 + 变化驱动 + 30s 心跳）、`mod/`（给上游 STS2MCP 打补丁）。

**注入点很讲究**：渲染结果 **unshift 到当前用户消息数组的第一段**，而不是 system prompt——理由是"让游戏状态跟对话轮次对齐，历史里的旧消息不受影响"。**Miracii 以后注入文档/软件状态可以照这个位置放。**

**幻觉成因（读源码后的推断，未找到公开评测或批评）**：主因是知识库自述"只记 2 代新增，1 代就有的不重复"，而 2 代对旧卡做过**数值平滑重做**（其文档自记 Bash 8→10、Inflame +2→+3）——**拿 1 代的记忆答 2 代的题**；次因是牌组/抽弃牌堆**只给卡名**（`game-context.js` L71–75、L126–133）、手牌卡面**截断 50 字符**（L191）、知识库是二手攻略编译、`PROTOCOL.md` L43 明写**无 schema 校验**。**结论：这是可修的载荷缺口，不是"模型读不懂卡牌体系"。**
