## 逐个拆解

### 1. dsh-fish-memory（1.6.0）——最接近「可调参数的遗忘曲线」

作者 Yuuyuko-uu。仓库 https://github.com/Yuuyuko-uu/dsh-fish-memory 。许可为自定义「Yuuyuko-uu 插件许可 1.0」（非 OSI）【R】。

**① 数据模型**【S】（`lib/index.js:3860`）
```json
{"id":"…","text":"她身高一米七","at":"ISO 真实时间","createdAt":"ISO",
 "category":"event|stable_profile","importance":0.0–1.0,"emotion":null,
 "tags":["≤6 个"],"source":"她自己记的","reinforcedAt":null,"lastReinforcedDay":null,
 "事实键":"她.身高",
 "activation0":0.0–1.0,"activationAnchor":"ISO","reinforceCount":0,
 "已被取代":{"被谁":"id","为什么":"…","作废于":"ISO"}}
```
- 存储：`~/.dsh/fish-memory/<sessionId>.json`，**一个会话一份**（不是跨会话共享）【R】。
- `category` 由 `importance>=1` 决定（`index.js:3865`）；另有「扩词 / 检索词」字段，由模型在提炼时顺手产出【S】。

**② 写入路径**【S】
- 唯一常规入口：模型调 `remember` 工具（`makeRememberTool`，`index.js:3658`）。工具描述里写死「一条只装一件事」「日常琐事不要记」「一天最多记一次」「不要说我记下了」。
- 写前校验：文本归一化后与库内比对，命中「同文或包含」→ **不新增，改为强化**（`index.js:3774`）；配额按北京时间自然日算（`index.js:2411`）。
- 事实键只在模型明确给的时候才写，**本地绝不从正文猜键**（`index.js:3267` 的注释：猜错会「悄悄埋掉一条正经记忆」）。
- 另有两条人工路径：旧档案导入后「开始提炼」（模型改写 + 出检索词/日期/重要度）、设置页「清洗补键」（先试 8 条只读）。

**③ 读取路径**【S】（`evaluate()`，`index.js:3089`）
```
第一道门（问句信息量，卡的是问句不是记忆）
  说话稀有(k) = ln((n+1)/(df_她说话(k)+1)) / ln(n+1)     # 她天天说的词≈0，偶尔说的≈1；n<20 不压
  信息量 < queryGate(0.8) → 一条都不给，理由记进 trace

证据量
  稀有度(k) = ln((N+1)/(df(k)+1)) / ln((N+1)/2)         # 裁到 [0,1]；N<=1 时有它就算 1
  s = Σ_k 稀有度(k) · 说话稀有(k) · 价(k)
      价 = 1.0（命中「扩词」整词）/ 0.8（扩词碎片）/ 0.6（只命中正文）
  C = s / (s + rarityK=0.8)
  整句原话命中（问句 ≥6 字）→ C = max(C, 0.85)

乘数
  A = A0 · 2^(−daysA/H)      H = baseHalfLifeDays(30) · (1 + 2I)
  E = emotion · 2^(−days/emotionHalfLifeDays(7))
  P = C · (0.55 + 0.25·A + 0.15·I + 0.05·E)
  时间词（「上周」等）命中且事件落在窗口内 → P × 1.3（只提排序，不给 C）
```
- 门槛卡的是 **C（证据）不是 P（总分）**。这是一次被写进注释的返工：早期门槛卡 P，调「没写时间的算多鲜活」会把整个库的分数一起压下去，实测「该想起的」从 10/11 掉到 5/11；改成卡 C 后同一批扫描 11/13 一动不动（`index.js:3154-3167`）。
- 排序后再按 `maxChars` 截断；同文条目在分名额**之前**去重（`index.js:3536`）。

**④ 遗忘 / 衰减**【S】
- 半衰期 `H = 30 × (1+2·importance)`，即 importance 0 → 30 天，1 → 90 天；情绪单独 7 天（`DEFAULT_POLICY`，`index.js:143`）。
- `stable_profile`（长期事实）不衰减，取常数 `unknownActivation`（默认 0.5）；没写时间的从「记下来那天」开始淡（`index.js:3072-3081`）。
- **不删**。README 原话：「不会自动删除记忆。淡忘只是越来越难想起来」【R】。
- 强化：`A' = A + 0.2(1−A)`，锚点重置为现在（`index.js:3790`）。注释特别写明：**只有她又提一次才强化，光是召回想起来不强化**（「仅浏览、搜索不会把记忆越看越重要」，`index.js:3770`）。

**⑤ 去重 / 冲突**【S】
- 同文：归一化（去空白与中英标点）后全等或互相包含 → 强化。
- 近重：`像度 = |A∩B 词| / |较短那条的词数|`，阈值 0.85（`index.js:3224`）。作者记录了实测：三字片段像度 ≥0.85 一对都抓不到、词像度 ≥0.85 抓到 85 对；人眼看 0.70~0.80 那 46 对「绝大多数是真重复」。
- 事实键：`对象.方面`，做全角点/大小写/分隔符归一，长度 ≤24；**万能键黑名单**（最后一段正好是 内容/相关/记录/事项/事情/杂项… 一律当没填），因为真数据里出现过「我对她说过的话.内容」把四句不相干的话收成一条（`index.js:3285-3302`）。
- 收敛规则：同键只留最新（先比 `at`，没有比 `createdAt`，都没有排最后），旧的标「已被取代」——不再注入但留着、可撤销（`index.js:3304`）。

**⑥ 注入预算**【S】
- `maxItems: 6`、`maxChars: 800`、`dailyQuota: 8`（`DEFAULT_POLICY`）。
- 1.5.7 起**删掉了「长期事实每轮无条件带几条」这一层**（`index.js:3567`），事实也要靠证据进。
- 注入形态（`render()`，`index.js:3624`）：`【你记得的事】` + 一句规则（有时间就按时间说、不知道就说不知道、别编）+ 每条一行；`at` 存在写相对时间，`stable_profile` 写「一直：」，不知道时间就不写时间。

**⑦ 可解释性**【S】
- `traces`（最近一次召回）逐条带 `omission`，取值：`hard_gate` / `below_threshold` / `limit` / `budget` / `query_gate` / `duplicate` / `weak` / `fact_cap`，UI 翻成中文（「没命中线索」「分数不够」「字数超了」「问句没内容」…，`index.js:4270`）。
- 「这条有没有被用上」是**猜的**：回复与记忆的实词重合 ≥2 个且占比 ≥1/3 就叫「像是用上了」（`index.js:3601`），作者自己注明「所以设置页上写『像是用上了』，不写成『用上了』」。

### 2. dsh-hierarchical-fishmemory（1.9.7）——分层 + 双预算 + 唯一会消失的一层

作者 MarsStorm。仓库 https://github.com/MarsStorm/dsh-hierarchical-fishmemory 。MIT；日记引擎来自上游 feiyu-memory 4.0.2（作者 空气凤梨，https://github.com/AirPineApplea/feiyu-memory ）【R】。

**① 数据模型**【R】【S】（`src/core/*.mjs`）
```
~/.dsh/feiyu-diary/
├── 日记.md            ← 人看的视图（自动生成，改它没用）
├── diary/2026-10.jsonl ← 真数据，一行一条：{text, kind, salience, created_at, recall_count}
├── diary/archive/      ← 45 天前压成月摘要后的原文
├── 鱼的日子.md         ← 情感日记（手写，不衰减）
├── 手记.md             ← 人格手记（`- ` 开头，每轮全量注入）
├── shallow.json        ← 浅层：每条带 expiresAt / updated / tags / key
├── relationship.json / lexicon.json / dates.json / manifest.json
~/.dsh/soul-md/memory/<卡片名>/{core.md, topics/*.md}
```

**③ 读取路径**【S】（`src/core/recall.mjs`）
```
BM25: k1=1.2, b=0.75, IDF_SMOOTH=1
  idf(t) = ln(1 + (N+1)/(df(t)+1))
  gain   = w·tf·(k1+1) / (tf + k1·(1−b+b·len/avgLen))
  raw    = Σ gain
归一到 0–1： sim = min(1, 1 − e^(−raw/2))        # saturation = 2
新鲜度： fresh = 0.5^(ageDays/45)                  # halfLifeDays = 45
冷却：   turn − lastShownTurn < 20 轮 → 直接出局
打分：   score = 1·sim + 0.45·salience + 0.2·fresh − 0.8·(曾被摆出来过)
                + 0.15（kind=failure 且 resolved≠true）
三档出货：sim ≥ 0.5 强匹配必出 → 不足则 sim ≥ 0.25 且 salience ≥ 0.5 的池里 softmax(温度 0.15) 抽 1 条
          → 一条都没选中时，8%（wanderChance）随机「走神」想起一条

- 浅层续期：正文里出现它的 key 或 tags → 重置倒计时。

relief    = min(0.5, 0.5 · ln(1+recall_count)/ln(1+10)) # recallReliefFullCount = 10
被召回过： factor = 0.9^(days · (1−relief))
salience' = max(0.16, salience · factor)               # salienceFloor = 0.16
性格特质： salience' = max(0.16, salience · 0.97^days)
```

- LLM 摘要：输入最近 **60** 条消息，要求只输出 JSON：`{"summary":"200-300 字，第二人称，概括剧情/角色状态/重要事件/未完成线索","relations":[…]}`。
- 落库前做字符级净化 `sanitizeModelText`：剥 HTML 标签、`on*=` 事件、`javascript:|vbscript:|data:` 协议、控制字符；注释明确「只做字符级/标签/协议剥离，不做指令性文本识别」，且「只在写入时净化」。
- 世界书是人手写，无写入路径。

**③ 读取路径**【S】（`lib/server/assemble.js:57`、`lib/utils.js:20`）
```
scanDepth = 4（只扫最近 4 条消息，注释：远小于原来的 20）
haystack = 最近 4 条消息拼起来的小写文本
for entry in entries:
    if entry.enabled === false: skip
    if injectMode === 'full': 全注入
    kwList = entry.keys ∪ entry.keywords
    if 任意 kw 是 haystack 的子串: 注入
拼装：【世界书 — 关键词触发条目】+ 每条 `## name` + `触发词：…` + content
```
- **没有打分、没有排序、没有 top-k、没有预算**。注入多少取决于命中多少条。

**④ 遗忘**【S】
- 没有衰减、没有 TTL。摘要每次重算覆盖上一份（不保留历史版本）。

**⑤ 去重 / 冲突**【S】
- 无。两个条目含同一事实会都注入；`secondary_keys` 已有解析函数但主路径只用 keys ∪ keywords 的子串匹配。

**⑥ 注入预算**【S】
- 世界书无 token 预算；角色卡硬顶 `CARD_MAX = 40000` 字（超出截断并加一句「卡片过长」）。
- 唯一可观测的是调试日志里的字符数。

**⑦ 可解释性**【S】（`assemble.js:74-79`）
- 每轮往 `.agent-presets/…/inject-debug.log` 追加一行：`世界书注入(ST): 常驻N条, 触发M/K条, 阶段选S条(跳过…), 跳过EJSN条, 总T条, X字符, isFull=…, 模式=…, 条目=[name[reason:chars], …]`。
- 铁律写在代码里：**只记条目名与原因，绝不记条目正文**（「正文是卡内容，进日志就是泄露」）。

### 7. DSH-a-complete-life-for-every-fish——工程化最彻底的一版（SQLite + 向量 + RRF + /why）

仓库 https://github.com/zhugeweimu/DSH-a-complete-life-for-every-fish 。Apache-2.0。A 版是独立 Python 服务（HTTP :8095），B 版只是 DSH 工具外壳、**不复制数据**【D】。

**① 数据模型**【D】（`sql/schema.sql`）
```sql
booku_memory_records(
  memory_id, title, content, person_id, folder_id, memory_type,
  importance REAL DEFAULT 0.5, created_at, updated_at, last_activated_at,
  activation_count, is_deleted, origin, author, source_event, version, namespace)
booku_memory_tags(memory_id, tag_type, tag_value)
booku_temporary_memos(stream_id, content, created_at, updated_at, expires_at)   ← 唯一带 TTL 的表
turn_logs(person, ts, user_text, reply_text, session_id, closed, event_id)      ← 每回合原样追加
event_records(person, start_ts, end_ts, summary, event_type, importance, weight,
              source_log_ids, legacy, is_archived)                              ← 关会话后合并
```

**② 写入路径**【D】
- `/remember` 直接写 SQLite；`/log` 可自动触发 autocapture（类型：fact / preference / plan / promise / relationship / event / note）。
- 写前两道去重：精确 `sha1(title|content|person)[:16]`；近重 Jaccard **> 0.8**，只扫同人最近 **300** 条。
- 重要度启发式：日记/自述 **0.9**，群聊 **0.15**，其余 **0.5**。
- 日志层与事件层分离：每回合先原样进 `turn_logs`，30 分钟会话分段，**关会话时**才合并成 `event_records`。

**③ 读取路径**【D】
```
BM25（中文二元） + bge 向量 + FAISS HNSW 粗筛 → 候选精确 cosine
RRF 融合，k = 60
可选 BGE reranker（ONNX），重排权重 0.2
总分 × (0.4 + 0.6·decay)
过滤 MEM_MIN_SCORE = 0.55
```
- `/context` 返回一段可注入文本 + items，示例参数 `top=5, max_chars=1200`。
- 明确「不自动注入」：塞不塞、塞多少由宿主决定。

**④ 遗忘 / 衰减**【D】（`docs/PARAMETERS.md`）
```
半衰期 H = 7 + 365·importance²   （天）
下限   floor = 0.3·importance
流水清理：群聊 且 7 天未激活 → 清理（_cleanup_flow）
```
- 即 importance 0.15（群聊）→ H≈15 天；0.9（日记/自述）→ H≈303 天。
- 软删除 `is_deleted`。

**⑤ 去重 / 冲突**【D】
- 精确指纹 + Jaccard 0.8 合并；**明确不做**事实槽位与改口失效，理由写在 README：「需要维护句式→槽名的映射，中文说法无穷，维护成本在我们这边；用模型抽槽又多一次调用且不稳定」。同样明确不做：话题聚合/固化摘要/存储压缩、来源隔离、历史会话回填、指代查询。

**⑥ 注入预算**【D】
- 内核不做注入；`/context` 由宿主给 `top` 与 `max_chars`（示例 5 / 1200）。文本超长在嵌入前截 500 字。

**⑦ 可解释性**【D】
- `/why`：解释某条关系/事件的证据（默认返回 5 条）。
- `/profile?person_id=`：人物档案（印象/特征）。
- `vault/` 导出：`index.md` + `memories/日期/` + `日记/` + `自述.md`——**人能直接翻**。

### 8. 相邻两个：dsh-fish-river 与 dsh-fish-mood

**dsh-fish-river**（合并版，已停止维护，作者转做 dsh-roost）【R】
- 三层记忆，作者原话「只有一层是『她』」：
  | 层 | 存在哪 | 能不能改 | 谁写 |
  |---|---|---|---|
  | 成长（她是谁） | `events.jsonl`，只追加 | 不能改，只能被后来的事推翻 | 系统 |
  | 关系（她记得谁） | `people.json`，一人一条，印象 ≤150 字 | 她能自己覆盖/清空 | 她 |
  | 流水（最近说了什么） | `journal.json`，每会话最近 30 句 | 滚动淘汰 | 系统 |
- **流水不进事件流**——「群里刷屏不该改变她是谁」。
- 合并 dsh-fish 与 fish-soul 时踩到的坑写得很直白：「一条事件流、全局召回，群里陌生人 @ 她一句，她能翻出私聊内容」→ 事件加 `person/visibility/channel/origin`，进出站都过可见性闸门与泄漏检测。
- 明确放弃 BM25 + 向量：「向量要 embedding 服务，等于破掉零依赖和『数据只在本地』」。

**dsh-fish-mood**（0.1.0，情绪不是记忆，但常被混为一谈）【S】
仓库（据 `agent-ecosystem.txt` 索引）https://github.com/ChencLi819/dsh-fish-mood ；本次读的是 npm 包 `dsh-fish-mood@0.1.0`。
```
每种情绪带半衰期（分钟级）+ 掩饰能力 + 评价签名
衰减双指数： remaining = (1−0.28)·0.5^(t/(0.6·hl)) + 0.28·0.5^(t/(3·hl))
强度修正： hl_eff = hl × (0.75 + intensity/400)
底色按作息 8 段回归基线；强情绪可「续命」至多 3 次
```
- 设计边界写死：**只改表达，不改事实**；静态规则段字节不变（保缓存），实时状态段单独注入。
- 这条对 Miracii 的意义：`memory-frontier.txt` 引 ZifaMem 的结论「额外情绪状态机无任何端点增益」，而 Miracii 已有 warmth 六轴——不要再加第二套情绪。

## 失败模式

按「设计的固有短板」列，每条给代表与机制层原因。

**1. 纯字面召回：不可控，且越修越像调参工程**
- 代表：dsh-fish-memory（最典型，因为作者把踩坑写进了注释）、soul-md、tavern。
- 机制原因：字面匹配的假阳性来自「单字撞进长词」「常见词当证据」「五个弱证据攒成强证据」。dsh-fish-memory 为此叠了五层（词表切分、说话稀有度、扩词价、稀有度饱和 `s/(s+0.8)`、问句信息量门），仍要承认「实测 851 条里 833 条没时间戳」这类分布问题会反过来影响打分。
- 固有短板：**召回质量与语料规模强耦合**，换个语料就要重调；而参数是「口味值」，没有客观最优。

**2. TTL 造成结构性失忆**
- 代表：hier 的浅层（7 天）。complete-life 的群聊 7 天未激活直接清理更狠。
- 机制原因：TTL 用「时间」近似「重要性」，但**重要但不常被提的事**（一年一次的纪念日、一次性的承诺）恰好最容易被 TTL 杀掉。
- 设计上的补丁也能说明问题：hier 必须配 `shallow_promote`（人工升格）、`expired` 尾巴（最后一次机会）、`WARN_DAYS=2`；且 README 的「已知限制」直接写「过期不会自动升级」。

**3. 事件流膨胀 + 派生层是单点**
- 代表：dsh-fish。
- 机制原因：append-only + 全量重放 = 账本永远在长；派生逻辑（`derive.js`）一个 bug 会污染身份文档的全部段落。它必须自带 `compact`、观测台、`selfcheck`，运维面显著变重（包体 5 MB，仅 `derive.js` 63 KB）。
- 固有短板：**审计性强，但读写成本随时间线性增长**；单人项目很难长期维护派生层。

**4. 双重记忆源互相覆盖**
- 代表：hier（一个包两个 cordis 入口，`includePersona` 默认关就是怕「两份人格同时进 prompt，互相打架」）；tavern（世界书 + 会话记忆 + 预设三处都可能写同一事实）。
- 机制原因：多个写入者 + 没有事实键 = 冲突只能「报告」不能「裁决」。hier 的 `fish_layer_check` 明说「只报告，不改任何东西。删哪份、留哪份，得由写它的人判断」。
- 固有短板：**报告型一致性检查把决策成本推给人**；不看的用户永远带着矛盾注入。

**5. 摘要丢细节，且摘要不可回溯**
- 代表：tavern（200–300 字覆盖式）、hier 的 `fish_compact`（但 hier 保留了 archive，可回查）。
- 机制原因：摘要是**有损压缩 + 覆盖写**；一旦覆盖，原文若没归档就永久丢失。tavern 的会话记忆没有版本。
- 固有短板：压缩比越高，「为什么她记错了」越不可解释。

**6. 向量召回：不可控 + 运维成本 + 破坏「数据只在本地」**
- 代表：fish-soul（远程 OpenAI 兼容 embeddings，800ms 超时 fail-open）、complete-life（bge + FAISS + 8081 服务）。
- 机制原因：embedding 服务是外部依赖；跨模型换版本要重测阈值（complete-life 的参数文档直接写「换嵌入模型必须重测 近重阈值 与 MEM_MIN_SCORE」）。
- 反证：fish-river 明确放弃；`memory-frontier.txt` 里 Amory 也不用 embedding，且其证据表明相似度检索会污染上下文。

**7. 预算硬顶 = 另一条失忆路径**
- 代表：soul-md（8000 字符）、hier（2000 token）、fish-memory（800 字 / 6 条）。
- 机制原因：预算是「成本封顶」，但封顶处没有重要性兜底时，刚好被挤掉的可能正是关键那条。soul-md 的 `retainMemoryEnds`（保首尾）与 hier 的 `pinRecent`（压缩后重灌）都是补救；fish-memory 更直接——超预算就不进，「下次可能就进了」。
- 固有短板：**预算与召回质量是同一根绳的两头**，没有任何一版给出「预算内最优」的证明。

**8. 可解释性 ≠ 正确性**
- 代表：fish-memory 的「像是用上了」（实词重合猜的）、hier 的 `why`（只标命中类型）、tavern 的 debug log（只记名字与字数）。
- 机制原因：解释的是**打分链路**，不是**语义是否正确**。一套自洽的打分可以稳定地召回错的东西，而解释看起来毫无破绽。
- 这是最容易被误读成「可观测」的坑：日志齐全 ≠ 记忆对。

**9. 参数化过度**
- 代表：fish-memory 12 个旋钮（权重 4 项必须合计 100%，由 `fitWeights` 凑数）、complete-life 一整页 PARAMETERS、fish-mood 36 情绪各带半衰期。
- 机制原因：每个旋钮都要有默认值理由、范围、互相影响说明；作者自己写「这些值都是经验值/口味值，不是硬约束」。
- 固有短板：**单人项目调参成本 > 收益**；参数越多，回归越不可测。

**10. 没有去重的那一层，最后都靠人**
- 代表：tavern（重复条目重复注入）、soul-md（靠 `memory_rewrite`）、complete-life（Jaccard 0.8 只解决近重，不解决矛盾）。
- 机制原因：**「相似」和「同一件事」不是一回事**。fish-memory 的注释把这个区别写得最清楚：「她身高一米七」与「长胖到 55 公斤」词面很像却是两件事；「拼团还没开」与「拼团开了」词面不像却是同一件事的前后。

## 与 Miracii 现有架构的对照

Miracii 现状（本文件写作时核对过）：
- 文件树 `persona/<id>/memory/{working,impression,episodic,semantic,calendar,lore,learn_queue}`，全部人可读文本；`_template/` 有样例；`holmes-test/` 是另一人格。
- `memory/starmap.jsonl` 是**投影 sidecar**：一行一个星点，字段 `file/block/fp/kind/level/ew/rc/last/created/src/state`，只追加、软删除（`persona/miracii/memory/starmap.jsonl` 首行实测形如
  `{"file": "memory/impression/2026-09-02.txt", "block": 0, "fp": "f676a69301cd", "kind": "impression", "level": 2, "ew": 0.3, "rc": 0, "last": null, "created": "2026-09-02", "src": "impression:2026-09-02.txt", "state": "active"}`）。
  注：`docs/STARMAP.txt` 描述的是 `anchor.file` / `anchor.block` 嵌套形态，与实际落盘字段（扁平 `file`/`block`/`fp`）不一致——**文档与数据对不上，需另开一条修正**。
- 衰减（`app/starmap.py:74-141`）：
  `λ(ew)`: ≥0.8→0.005 / ≥0.6→0.01 / ≥0.4→0.02 / 否则 0.04（半衰期 138.63 / 69.31 / 34.66 / 17.33 天）；
  `decay = exp(−λ·days)` 从 `created` 算；
  `recallBonus = min(0.3, ln(1+rc)·0.08)`（rc≈41.5 饱和）；
  `brightness = min(1.0, decay + recallBonus)`；`mag = 6.5 − 5.5·brightness`。
- 检索（`app/recall.py`）：`relevance = 3×命中 keys 数 + 2×(who 命中)`（semantic），sitting 用 `sum(len(k))`；排序 `relevance × decay × novelty(rc)`，`novelty = max(0.3, 1/(1+ln(1+rc)·0.5))`；预算 `MAX_HITS=8 / MAX_SITTINGS=2 / BLOCK_CHARS=900`；只注入命中 keys 的块；同指纹只出一块。
- 写入：巩固链（`app/supervisor.py:apply_decision`）——「Adopt daily facts/calendar; queue patterns. Never rewrite profile or lore.」；`starmap.jsonl` 由宿主落盘，模型只打分。

### 做得到（文件树 + sidecar 能承载，且不破「人可读 / SHA256 守卫」）

1. **三维打分 + 门槛卡「证据」而不是卡总分**（fish-memory 最贵的那条教训）★最值得
   - 现状 `_priority()` 已把 `relevance × decay × novelty` 乘起来；缺口是**没有独立的「相关性阈值」**：现在只要 relevance>0 就进候选，靠条数与字数截断。
   - 可做：给 `recall.py` 加 `C` 式的相关度归一（`C = s/(s+K)`），门槛卡 `C`，把 `decay`/`novelty` 只留给排序。这正好复刻 1.5.7 那次返工的正确形状，且**纯代码改动、不动文件**。
2. **「事实键 + 已被取代」取代「同指纹去重」**
   - `semantic/` 行本身是 `who | claim | … | keys`，`keys` 就是天然粗粒度事实键（现有 `keys:` 行格式已在用）。
   - 可做：`starmap.jsonl` 加 `fact_key` 与 `superseded_by`，同键只让最新那条进注入；旧块 `state` 保持 `active`（不删、不 retired，因为 retired 的语义是「指纹失效」）。
   - 注意：**不要自动从正文猜键**（fish-memory 的万能键事故：`我对她说过的话.内容` 把四句话收成一条，`index.js:3285`）。Miracii 没有「模型可直接写记忆」的通道，键只能由人写在 `keys:` 里或巩固链给。
3. **召回解释（trace）**★最值得
   - `starmap.jsonl` 已有 `rc` / `last`；缺的是「这次为什么进/为什么没进」。
   - 可做：`memory/recall-log.jsonl`（派生文件，可删可重建，符合红线），每条记 `{ts, query_tokens, hits:[{src, relevance, decay, novelty, C, rank}], dropped:[{src, reason}]}`；`reason` 直接照抄 fish-memory 的枚举（`below_threshold / limit / budget / duplicate`）。报告面上它比 star map 更有用。
4. **注入预算从「条数」升级为「条数 + 字数」双上限**
   - 现在 `MAX_HITS=8 / MAX_SITTINGS=2 / BLOCK_CHARS=900` 只对单块截断，没有总字数封顶。
   - 可做：`format_for_prompt` 里加总字符预算（800–1200），超了按 `_priority` 尾部丢弃并记进 trace。
5. **体检：重复句 / 矛盾值报告**（hier 的 `fish_layer_check`）
   - 纯读文件即可：同一句出现在 `impression` 与 `episodic`、`semantic` 两行同 who 不同 claim、`lore` 与 `semantic` 冲突。只报告不改动，符合「不动 persona 内容」。
6. **「快忘了的 / 快固定了的」两栏**
   - 用现成的 `decay` 与 `rc` 就能算：`decay < 0.2` 且 `rc = 0` → 快忘了；`rc ≥ 20` 且 `ew ≥ 0.6` → 快固定。这是 dsh-fish「查一下」最便宜的一半。

### 做不到（或代价明显超过收益）

1. **每轮 LLM 固化**（hier / tavern / complete-life 的抽取）
   - Miracii 的写入是异步巩固链 + 人可改；每轮一次 JSON 抽取 = 每轮一次模型调用 + 延迟 + 失败面，而本地语料只有 0.1 MB 量级。**不值得为这点语料付每轮成本。**
2. **向量 / embedding 召回**（fish-soul、complete-life）
   - 语料太小，`memory-frontier.txt` 已引 Amory 的证据：相似度检索会污染上下文；且 Miracii 明确不建向量库（STARMAP §8）。**维持不建。**
3. **事件溯源全量重放**（dsh-fish）
   - 需要把聊天全量落成不可变事件流 + 一套可重放的派生层。Miracii 已有 `transcript/` 与分层文件，但**没有 rebuild 语义**；照搬等于把 `starmap.py` 从「投影」升级成「真相源」，与红线 1（不改 persona 内容）和「派生值不落盘」原则冲突。
   - 折中可做：只对 **starmap sidecar** 做「重建」能力（删掉 jsonl 能重扫出来）——这条现在其实已经具备。
4. **SQLite 多表 + 时间窗查询**（complete-life）
   - 技术上不难，但会把「人可读的文本文件」变成「要看 SQL」。**与项目定位冲突，不做。**
5. **多人 / 群聊隔离**（fish-soul 的 `private`、fish-river 的 `person/visibility/channel`）
   - Miracii 是单人单机；没有第二个 owner。**不需要。**
6. **云端备份（WebDAV）**
   - hier 支持，但把记忆/人格/凭据推到第三方网盘；Miracii 的隐私面本来就小，**不值得开这个口子**。

### 不值得做（机制本身有问题，不是实现问题）

1. **36 情绪状态机**（fish-mood）
   - `memory-frontier.txt` 已引 ZifaMem：情绪状态若不与记忆/关系耦合，单独加一层在评测上无收益；Miracii 有 warmth 六轴，再加一套会打架。
2. **参数面板化**（fish-memory 12 个旋钮）
   - 单人项目没有调参的人力与样本量；参数一旦暴露，默认值就成了「用户以为自己调对了」的假象。**常数写死在代码里 + 注释写清理由**更符合本仓库风格。
3. **TTL 删除**（hier 浅层、complete-life 群聊清理）
   - 与「人可读、可回查」冲突。若要「7 天后不再注入」，正确做法是 `state: deferred` + 到期时间，**文件仍留着**（starmap 已有 `deferred` 状态位，未启用）。
4. **覆盖式摘要**（tavern）
   - 没有归档就是不可回溯；hier 至少留了 `archive/`。Miracii 的 `episodic/` 本来就是原文归档，不需要再引入一层摘要。
5. **万能事实键的自动生成**
   - fish-memory 自己踩过、自己加了黑名单。没有「模型写记忆」通道时，自动生成键只会制造沉默的错误。
6. **把「召回计数」当重要性**（brightness 已刻意分开）
   - Miracii 的 `novelty` 地板 0.3 已经处理过这个坑；**不要**因为某个插件用 `rc` 加权就把它并回排序。

### 一句话判断

**「文件树 + sidecar」完全能承载这些插件里真正值钱的三件事——按证据阈值召回、按半衰期衰减但不删、逐条解释为什么想起；承载不了的是每轮 LLM 固化、向量检索、事件溯源重放——而这三件恰好也是它们各自最贵、最容易坏的部分。**
