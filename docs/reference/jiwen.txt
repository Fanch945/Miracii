## 主张

**不靠概率骰子**：用五个连续数值的确定性漂移替代"每 N 分钟 roll 一次"。同样的状态输入得到同样的行为输出——可复现、可调试、可回答"她为什么此刻开口"。实测全仓库 `jiwen/` 目录**零 `Math.random`**，主张属实。

## 五轴（`jiwen.js` L30–36）

| 轴 | 范围 | 含义 |
|---|---|---|
| connection 连接需求 | 0→1 | 多久没听到对方，想念在累积 |
| pride 骄傲 | -1→+1 | 端着还是放软；**被冷落时防御性上升** |
| valence 愉悦度 | -1→+1 | Russell (1980) 环状模型 |
| arousal 唤醒度 | -1→+1 | 与 valence 正交 |
| immersion 沉浸度 | 0→1 | 专注程度，也是**骄傲的缓冲垫** |

## 阈值（L113–120，写死在 `Object.assign` 默认值里）

```
observation      0.20      注意到沉默，但还没想动
considerContact  0.35      开始犹豫要不要开口
forceContact     0.50      强制开口（pride 挡不住）
prideBlock       0.50      骄傲高于此值 → 转为"找事做"
valenceActivity -1.0       低至此值触发自我调节（-1.0 = 永不）
arousalAgitation 0.7       高至此值也触发自我调节（躁动难坐）
```

## 三道闸门 + 两道并列闸门（L441–529）

1. `connection ≥ 0.20` → `observation`（**内心念头，不发出**）
2. `0.35 ≤ connection < 0.50`：
   - `pride ≥ 0.50` 且 `immersion < 0.2` → `find_activity`（逃避/自我调节）
   - `pride ≥ 0.50` 且 `immersion ≥ 0.2` → **什么都不发**（沉浸在事里，面子有缓冲）
   - `pride < 0.50` → `contact`
3. `connection ≥ 0.50` → 强制 `contact`（`forced: true`）

并列：`valence ≤ valenceActivity` 或 `arousal ≥ arousalAgitation`，且 `immersion < 0.3` → `find_activity`。

## 漂移（主公式 L266）

```
effectiveRate = baseRate × accelFactor × valenceMultiplier × max(0, immersionFactor)

accelFactor     = pow(1 + connection, connectionAccel)   # L249-251，仅当距上次消息 ≥ accelDelay 分钟才启用
immersionFactor = 1 - immersion × immersionDampenConnection   # L262-264
单次 tick 上限 60 分钟                                        # L209
```

轴间制衡是这个引擎的性格所在：连接需求到阈值但骄傲高 → 不开口、转而找事做；低 valence + 高 arousal → 烦躁带刺；低 + 低 → 低落话少；等待拉高 arousal，同时锁定 valence 回归（想念越重，坏情绪越难消散）。

## 我方取舍（P1 决定）

**抄**：确定性替代随机；数值翻成人话再进 prompt；阈值起点（0.20/0.35/0.50/0.50 + 加速度 1.0 + 缓冲 45 分钟）；**决策轨迹从一开始就做**（她是后期补的）。

**不抄**：`immersion` 那种角色特化的轴定义直接硬编码（要拆成"通用轴 + 人格特化轴"）；对外 npm 接口。

**要加**：
1. **轴空间可配**（通用轴 + `persona/<id>/` 特化槽位）；
2. **一条 hesitation（犹豫）轴**，抬高 `contact` 阈值并给出"欲言又止"的样式指令——**用显式状态实现不确定度，不用随机数**，否则就退回骰子了；
3. **`user_state` 输入**（由轻量模型从最近对话推断：忙碌/放松/低落），作为 `contact` 阈值的调制因子——把"角色中心"推向"关系中心"（参照 ProMemAssist 的批评）；
4. **LLM 只做两件事**：把状态翻译成人话、对阈值做一次性微调；**积分永远由确定性代码做**。

（顺带：第 3 条前辈其实已经留了口子——`DEFAULT_STATE.userStatus` 字段与 `setUserStatus/getUserStatus` 都在，
只是**没有任何默认调制**；我们这版把它接到了门槛上。）

## 规格纠正的三个预期（2026-10-14 核实）

| 原本以为 | 实际 |
|---|---|
| 有 `analyzeChatSegment` 做对话分析 | **不存在**（无定义无导出，仅 jiwen.js:277 一句注释提及）。引擎侧唯一入口是 `applyDelta(delta)`，**夹紧在调用方**（GUIDE.md 规定前三轴 ±0.3、connection −0.5~+0.3） |
| `getSagaBias` 是实例方法 | **不是**。只有可选回调 `opts.getSagaBias`（jiwen.js:215-221），按轴读加性偏置；同理还有 `opts.getCircadianBias` |
| 冷启动各轴默认 0 | **不是**。`DEFAULT_STATE` 取各轴**下界**（`pride=-1, valence=-1, arousal=-1`）；`opts.initialState` 只有 JSDoc 声明、实现从未读取。她自己的测试也绕过它（用 `onLoad` 注入中性状态） |

**我们这版有意偏离**：初始值取 0（中性），不取轴下界——因为那等于让她一开机就"骄傲见底、心情最差"。
偏离点记在这里，不藏在代码里。
