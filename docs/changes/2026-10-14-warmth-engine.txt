## 背景

主动开口在 Miracii 里是**结构性饿死**的：25 天 25 次 tick，`speak=true` 零次。根因不在提示词——`clock.due_phase()` 只返回巩固阶段，supervisor **从没有机会**回答"我现在想不想找她"；`schedule.tick_minutes` 被解析但从未被任何代码读取。

P1 按已决定的分步走：**先通用引擎，再 template，再人格特化**。这一步只做通用层——借 `ClaraShafiq/jiwen` 的思路重写，不是移植。

## 改了什么

| 文件 | 改动 |
|---|---|
| `app/warmth.py` | 新增。确定性引擎：五轴漂移（connection / pride / valence / arousal / immersion）＋ **hesitation 轴** ＋ 声明式 `extra_axes` 特化槽位 ＋ `user_state` 门槛调制 ＋ 决策轨迹（每闸门报"差多少/过了多少"）＋ 数值翻人话（`prompt_context` / `style_guidance`） |
| `tests/test_warmth.py` | 新增。34 项：确定性、60 分钟上限、各轴漂移、闸门三选一与互斥、犹豫与 user_state 调制、特化轴、NaN 防护 |
| `docs/reference/jiwen-spec.txt` | 由子代理逐行读出的规格（745 行，带行号与 SHA256 基线）搬进仓库，供两个 agent 共查 |
| `docs/reference/jiwen.txt` | **订正两处我写错的地方**（见下） |

阈值继承前辈**调参后**的起点（0.20 / 0.35 / 0.50 / 0.50、加速度 1.0、缓冲 45 分钟），不是它的出厂值。

与规格逐条对齐过：`tick` 早退（`minutes<=0` 不推进）、单次上限 60 分钟、`accelFactor=(1+c)^accel` 仅在超 `accelDelay` 后启用、`effectiveRate` 四因子乘积、immersion 衰减用 `min(mins, sinceActivity)` 并在 `<=0.01 且 >60 分钟`时清空、pride 的防御/回归、valence 锁定、arousal 的"回归力不越过设定点"特判、**开口类闸门三选一互斥**、`triggers.length ∈ {0,1,2}`、`forced` 只在强制线出现。

## 有意偏离参照实现的地方（都写进文档，不藏在代码里）

| 偏离 | 理由 |
|---|---|
| 初始值取 0（中性），不取轴下界 | 参照的 `DEFAULT_STATE` 取 `axes.X[0]`，冷启动是 `pride=-1, valence=-1, arousal=-1`——等于一开机就"骄傲见底、心情最差"。她自己的测试也绕过这点（用 `onLoad` 注入中性状态） |
| `apply_delta` 丢弃非有限值 | 参照无 NaN 防护，`clamp` 会让 NaN 穿透并**永久污染该轴** |
| 闸门轨迹用具体名字（`contact` / `force_contact` / `blocked`…）而非只有"开口/自我调节"两组 | 调试时想知道是**哪一条**挡的 |
| `urgency` 用真阈值算，不用硬编码的 0.30 / 0.40 | 参照里那两个数是写死的，改了阈值就对不上 |
| `user_state` 接到门槛上 | 参照有 `userStatus` 字段与 setter，但**没有任何默认调制** |
