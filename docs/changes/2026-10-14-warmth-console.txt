## 背景

人的原话：之前想的是"应用中的文件、记忆查看窗口有一个简单的命令行可以 `ls`、`open` 打开文件等功能，
**能不能复用，在那里也可以看 `app.warmth --watch` 之类的**"；并说"看看工作量决定要不要先做，可以先放进备忘录"。

读了 `app/static/console.js`（267 行）后判定：**它是纯前端的白名单命令分发器**——
`runCommand()` 里 `help` / `refresh` / `runtime` / `ls` / `open` 五个命令，输出就是往文本框写字符串，
数据全部走已有的只读接口。所以加命令是**小活**（约 50 行 JS、零后端改动、零新依赖），**决定直接做**；
真正大件的部分写进备忘录。

### 一条明确的"不做"

**应用内的真终端（PTY / 任意 shell）不做**，理由写进备忘录了：应用支持 `--lan` 把端口开到 0.0.0.0
给手机用，而现有接口**没有鉴权**——网页里的 shell 等于把这台机器交出去。命令窗口现在这个
"白名单分发器"结构本身就是安全边界。要加能力就**再加白名单命令**，不是加终端。

## 风险与未决

- **交互未在浏览器里验过**：`warmth watch` 的定时器、`mark` 的参数解析都只做了静态检查与接口测试。
- `mark` 命令行版**只支持结论 + 说明**，维度辨析（`blame`）与标签要回面板填。
- 命令窗口的输出是纯文本，不做折行控制；窄窗口下进度条那一行会偏长。
- 备忘录里的条目没有排期，只是把"想做/不想做/卡在哪"记下来，避免下次重新讨论一遍。

## 复核（Cursor / 2026-10-14）

三条命令都在，`help` 列了它们，输出走 `textContent`，`warmth watch` 的间隔是 3 秒。`node --check app\static\console.js` 通过。`test_the_command_window_knows_the_warmth_commands` 只检查源码里有这几个字符串。我用临时 DOM 加载了这份 `console.js`（仓库里的文件没有改），把命令跑了一遍。

`mark ok_silent 他在开会` 发出去的是 `verdict: should_speak`，说明是 `ok_silent 他在开会`。`mark should_stay_silnt 说明` 同样是 `should_speak`。词写对了的 `should_stay_silent` 才会记沉默。服务端 `mark(verdict="ok_silent")` 在临时台账上收成 `should_stay_silent`。`app/static/console.js` 241–244 行：第一个词不在三个名字里，就当成省略，结论改成 `should_speak`，那个词并进说明。别名和拼错都会记成「她该开口」。

`warmth watch` 开着再输入 `mark`，定时器还在。画面先写出「已记下：[should_speak] 还在看」，下一次刷新盖成「# 积温 miracii」。`help` 也不停。`docs/WARMTH.txt` 180 行写的是换人格或跑别的命令也会停。`console.js` 303 行的 `mark` 分支没有 `stopWatch()`。

节奏行打出来是「积压 0」。这次接口给的是 `backlog` 0、`backlog_total` 18。面板和 `watch_line` 写的是新鲜/总。

最该先修：`app/static/console.js` 243 行。认不出的结论应拒绝这条命令，或把原词交给 `mark()`：`ok_silent` 会收成 `should_stay_silent`，未知收成 `unsure`。

```powershell

```

临时 DOM 里三次 POST 分别是 `should_speak` / `ok_silent 他在开会`、`should_speak` / `should_stay_silnt 说明`、`should_stay_silent` / `他在开会`。未改 `app/`、`tests/`、`persona/`。
