# 改动登记：DSH 与 Cursor 的公共账本

谁动了这个仓库，谁就在这里留一条记录。另一个 agent 复核时把意见写进**同一条记录**，
而不是散在各自的对话里——对话会丢，文件不会。

## 要不要登记

一句话判据：**改完之后，别人要重跑一次或重读一次代码才知道行为变了 → 登记。**

| 要写 | 不用写 |
|---|---|
| 应用行为、数据格式、接口、启动方式、依赖、文件约定 | 错别字、格式化、纯注释、只改文档措辞 |
| 动了 `app/`、`tests/`、`requirements.txt`、`docs/*.txt`（设计文档） | 只动 `docs/changes/` 自己的记录 |

拿不准就写。一条记录几分钟，一句「这什么时候改的」半小时。

## 文件名与后续

```text
docs/changes/YYYY-MM-DD-<短名>.txt        例：2026-10-13-notify.txt
```

- **同一天、同一主题的后续改动**：追加到**同一条记录的「后续」小节**，不要另开文件。
- 另起一条却撞名时：用**时刻**区分（`-1530`），不要用 `-2`——两边都还没提交时谁也看不见谁的编号。
- `关联提交` 填提交后的短哈希；还没提交就写「未提交」，提交后回填。
  记录与改动在**同一个提交**里落地时，写「本文件所在提交」即可，不必回填哈希。
- **本规矩自身的改动**也按普通记录登记（`YYYY-MM-DD-ledger.txt`），不要只改本文件而不留账。

## 必备小节

用 [_TEMPLATE.txt](_TEMPLATE.txt) 起头：背景 / 改了什么 / 验证 / 风险与未决 / 复核。

- **验证**：只写**实际跑过的命令与输出**（长输出截断）。没跑过就写「未验证」，不要臆造。
- **复核**：留空，由复核方写。
- **后续**（可选）：同一主题的追加改动。

## 角色：谁写哪一节

| 节 | 谁写 | 内容 |
|---|---|---|
| 背景 / 改了什么 / 验证 / 风险与未决 | **作者** | 事实 |
| 复核（谁 / 日期） | **不是作者的那一方** | 意见，硬话直说 |
| 回应： | **作者** | 逐条答复：采纳 / 不采纳 + 理由 |

- 复核方**只追加，不修改对方写过的话**；分歧保留，不要抹平。
- 找不到第二方复核时写「暂无人复核」，**不要自己给自己写复核**。

## 复核方的默认动作

1. 动手改任何文件前，先记下要保护文件的 SHA256，事后比对，证明自己只动了该动的。
   这比在提示词里写「不要乱改」可靠得多（2026-10-13 那次就是这么确认的）。
2. 意见里带上**可执行的验证命令**，作者照跑一遍再回应。

## 和提交的关系

`githooks/pre-commit` 会跑测试；若暂存区动了 `app/`、`tests/`、`requirements.txt` 或
`docs/*.txt` 却没动 `docs/changes/`，它会**打印提醒但不拦住**。想改成拦截：把环境变量
`CHANGE_RECORDS_STRICT` 设为 `1`。判据仍靠人。

## 和设计文档的分工

| 位置 | 内容 | 生命周期 |
|---|---|---|
| `docs/*.txt`（如 `NOTIFY.txt`） | 模块**怎么工作** | 长期有效，随代码更新 |
| `docs/changes/*` | **某一次**改动的账 | 写完不再改（只追加复核与后续） |
