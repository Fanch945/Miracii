## 背景

起因是人问了一句"她什么时候会涨积温、涨多久有效果"。为了回答，我用**真实配置**跑了一条 24 小时时间线——结果发现引擎的实际行为和它的文档不是一回事。以下六条都是**作者自查**（不是复核），逐条附可复跑的命令。

## 改了什么

| # | 问题 | 修法 |
|---|---|---|
| 1 | **`connection` 只涨不落**。`_drift_connection` 只有加法；能减速的只有 `apply_delta`，而**没有任何代码调用它**（参照实现把回落交给"对方回复时的 LLM delta"，那个调用方漏了）。后果：她一跨线就再也回不来，此后每 20 分钟想开口一次，把当天 3 条配额在一小时里烧完 | 新增 `on_user_message()` + `Config.reply_delta`（默认 `connection −0.25 / valence +0.05 / arousal −0.15 / hesitation −0.20`）；`app/main.py:389` 在存下 user 消息后调用（try/except 包住，积温出问题不影响聊天）。**等待由"你出现了"解除**，而不是她自己开口就自我安慰 |
| 2 | **开口太密**：冷却不存在 | 新增 `speak_cooldown_minutes`（默认 45）+ `State.last_spoke_at`；闸门里多一条 `cooldown` 记录（报还差多少分钟）；`heartbeat` **只在真的说出口之后**才 `note_spoke`。注：`schedule.txt` 的 `min_idle_minutes` 仍不读——它的语义是"至少闲置多久才可主动"，而 connection 涨到线本身就要 7 小时，天然满足；我做的是"两次开口之间的间隔"，是另一件事 |
| 3 | **骄傲永不防御**：`pride_defend_threshold = 1.0`（永不）是**出厂值**，我按"继承她调参后的起点"处理阈值与加速度时，把它漏在了出厂态。而"嘴硬、拉不下脸、转而找事做"正是这套设计最有性格的部分 | 改为 **0.35**：一进"有点想找对方"的带，防御就启动 |
| 4 | **`arousal` / `valence` 是摆设**：上升 0.002 < 回归 0.005、下沉 0.003 < 回归 0.005——**在任何 connection 下都涨不起来**，`arousal_agitation` 与自我调节闸门永远够不到 | 速率必须强过回归：`arousal_connection_rise_rate 0.002 → 0.0075`、`valence_connection_drift_rate 0.003 → 0.012` |
| 5 | **犹豫够不到可见强度**：它只在 `connection ∈ [0.35, 0.50)` 里长，而这个带只有两小时宽，骄傲爬到 0.5 时它已经结束了（峰值约 0.17，而"欲言又止"要 ≥ 0.5） | **去掉上界**：只要"还想找他"且"还端着"就一直在咽。语义上也更对——越久越咽回去 |
| 6 | **模板把默认值钉死**：`--write-template` 把三十来个速率全写进 `warmth.json`，等于**默认值从此对这个人生效不了**；引擎删掉的字段还留在文件里被报"不认识"（真实人格上已复现） | `template()` 改为**只列值得调的旋钮**（`--show` 才是全量）；重写真实人格的 `warmth.json`，漂移提示清零 |
| 7 | 上一份记录里我写"`effectiveRate` **四因子**乘积"，实际只实现了三个——**valence 那个乘子（boost/dampen）我压根没写** | 补上（`valence_connect_boost` / `dampen`，与参照一致默认关闭），并把它写进模板。**记录与代码现在一致** |
