# 记忆星图：结构说明（Miracii 版）

这份文档只描述**结构**，不描述内容。现有记忆文件（`working / impression / episodic / semantic / calendar / learn_queue` 与 `lore/`）与它们的分类树**保持不变**——星图是**投影**，不是新的存储层。

设计参照：`ClaraShafiq/MemoryConstellations`（MIT，已克隆在 `D:\SeelAI\ClaraShafiq\`）。我们只借四样东西：**情感权重分档驱动衰减**、**对数召回加成**、**亮度与检索优先级分离**、**指纹变化才重新裁决**。其余（星图可视化、五星系、双星核心、API 层）一律不抄。

## 1. 为什么放 sidecar，不写进记忆文件

元数据全部落在 **`persona/<id>/memory/starmap.jsonl`**，一行一个星点。

| 理由 | 说明 |
|---|---|
| 内容不可变 | 你要求不碰记忆与设定的实际内容；加一行也是动文件 |
| 手改不骗索引 | 锚点带正文指纹：手改过 → 指纹变 → 该星点退休，新块重新入册 |
| 可整体回滚 | 删掉这一个 jsonl 即恢复原状，不留残渣 |
| 派生值不落盘 | `decay / recallBonus / brightness / mag` 一律**现算**，避免双份真相 |

**将来若要写进文件**：只允许写 `lore/entries/*.txt` 的头部元数据区（那里本来就有 `keys:` / `form:` / `constant:`）。**正文块永不写。**

## 2. 星点字段

| 字段 | 类型 | 含义 |
|---|---|---|
| `anchor.file` | str | 相对 `persona/<id>/` 的路径，如 `memory/impression/2026-10-13.txt` |
| `anchor.block` | int | 该文件内的块序号（按 `# ` 分块，从 0 起） |
| `anchor.fp` | str | 该块**正文**的 sha1 前 12 位——锚定的真身 |
| `kind` | str | `impression` / `episodic` / `semantic` / `lore` |
| `level` | int | 层级：见 §4。用于仲裁 |
| `ew` | float | 情感权重 0–1，六档锚定（见 §3） |
| `rc` | int | 被检索命中次数（read count） |
| `last` | str | 最近一次被命中的日期 `YYYY-MM-DD`；入册时等于 `created` |
| `created` | str | 该块所属日期（从文件路径或块头解析） |
| `src` | str | 来源：`transcript/<id>#<msgid>` / `ext:<系统>` / `authored` |
| `state` | str | `active` / `retired` / `deferred` |

`starmap.jsonl` 只追加；同一 `anchor` 再次入册时写新行、旧行标 `retired`（**软删除，保留历史**）。

## 3. 情感权重 `ew` 的六档锚定

由巩固链（监督）在写入时打分；缺失时宿主兜底 **0.3**。

| 分值 | 锚定含义 |
|---|---|
| 0.0 | 纯事实，零情绪 |
| 0.2 | 轻微倾向，无情绪波动 |
| 0.4 | 有情绪色彩但不强烈 |
| 0.6 | 明显情绪 |
| 0.8 | 强烈情绪 |
| 1.0 | 极端冲击，触及核心（极少用） |

Miracii 的现成来源：`impression` 块的 **`气氛：` 行**。它已经写了"困、亲近、带点抱歉"这类东西——**不需要新增字段，只需要一个映射规则**（由监督在 routine/daily 时给分，或先用关键词表兜底）。

## 4. 层级 `level` 与仲裁

| level | 对应 | 粒度 |
|---|---|---|
| 1 | `semantic/`、`lore/entries`（digest） | 事实/词条 |
| 2 | `impression/`、`episodic/`、`lore/entries/stories` | 一场 |
| 3 | 长程弧线（暂不做，留位） | 一段关系 |

**仲裁规则**：同一 `src` 或同一 `keys` 命中多个层级时，**高层优先**；只有出现追问意图（`lore.STORY_INTENT`）才下钻到低层。现有的"多篇细稿同时命中就都不注入"保留，作为仲裁层的一个特例。

## 5. 衰减、亮度、星等

```
λ(ew) =  ew ≥ 0.8 → 0.005    半衰期 138.63 天
        ew ≥ 0.6 → 0.01     半衰期  69.31 天
        ew ≥ 0.4 → 0.02     半衰期  34.66 天
        else     → 0.04     半衰期  17.33 天

decay       = exp(-λ · days_since(created))      # 从"这条记忆是哪天的"算，不从"上次被读"算
recallBonus = min(0.3, ln(1 + rc) · 0.08)        # rc ≈ 41.5 时饱和
brightness  = min(1.0, decay + recallBonus)
mag         = 6.5 - brightness · 5.5             # 天文星等，越小越亮
```

**老化从 `created` 算，不从上一次被读算。** 参照实现用的是 `days_since_access`（被读就重置时钟），但那会造成一个后果：一条不断被注入的老梗会永远显得新鲜。我们改成——**老化是记忆自身的属性，复述只加亮度、并在排序上降权**。`last`（上次被注入）只做记录，不参与衰减。

半衰期按 `ln2/λ` 核算，与前辈注释的 139/69/35/17 一致（四舍五入差异）。

## 6. 最反直觉、也最重要的一条：亮度 ≠ 检索优先级

| 用途 | 公式 | 语义 |
|---|---|---|
| **亮度**（报告、亲切感） | 上面那套，**奖励 `rc`** | 常被想起的，显得更"亲" |
| **检索排序** | `相关度 × decay × novelty(rc)`，其中 `novelty = max(0.3, 1/(1+ln(1+rc)·0.5))` | 老梗降权，但**永不低于 0.3**，强匹配仍然赢 |

前辈用两套函数实现同一字段的两种语义。我们在 `recall.py` 里必须**显式分开**，否则会把"她常想起的"直接等同于"更该注入的"——那是改造前最大的隐性偏差。

`novelty` 的下限是有意的：没有下限时，一条被反复命中的事实会（在 rc≈100 万时）被压到 0.13，等于永久封杀；加地板后"相关度足够强就还是能进"，避免自锁。

## 6.1 落点：专属，不进总文件

`starmap.jsonl` **每个 `persona/<id>/` 一份**，因为它记的是"这个人格如何看待这些记忆"——情绪权重、被想起的次数，天然专属。

共享型数据（如 `data/` 下按人格筛选的运行时文件）与它不同：那是**同一份数据服务多个人格**；星图是**同一份记忆的不同人格视角**，混在一起会让两个人格的"亮度"互相污染。

## 7. 指纹与重新裁决

- 入册：算块指纹，`anchor` 不存在则新增；存在且 `fp` 相同 → **原样重试，标 `deferred`**，不做任何写入；
- 失效：原锚点的 `fp` 对不上现在的正文 → 旧星点标 `retired`，新块作为新星点入册；
- 因此**手改记忆是安全的**：不会污染索引，只会让那条记忆"重新入册一次"。

## 8. 不做的事

- 不建向量库、不建图库、不引入 embedding（语料 0.1 MB，且前辈的证据表明相似度检索会污染上下文）
- 不做星图可视化（没有前端，也不是瓶颈）
- 不改 `working / impression / episodic / semantic / calendar` 的格式与内容
- 不让模型直接写 `starmap.jsonl`：**模型打分，宿主落盘**

## 9. 验收

- 现有 22 项测试全绿
- 新增测试：锚点指纹、手改 → retire + 重新入册、原样重试 → deferred、亮度单调性（同 `last` 下 `ew` 高者更亮）、仲裁（同源只出高层）
- 一份**投影报告**（纯文本）：列出当前最亮/最暗的若干条，人工看一眼是否合理
